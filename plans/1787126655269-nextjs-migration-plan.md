# SautiFarm Next.js Migration Plan

## Goal
Migrate the entire SautiFarm codebase from Vite+React 19+Express to Next.js 15 (App Router), preserving all functionality, UX, and PWA features.

## Decisions (All Resolved)

| Decision | Choice |
|---|---|
| Routing | **App Router** (`/app` directory) — route per tab |
| API layer | **Next.js API Routes** — migrate Express server.ts; implement auth + M-Pesa |
| PWA | **Preserve with `next-pwa`** |
| Chat | **Dedicated `/chat` route** (full-page) + **simulated OTP auth** |
| Floating chat button | **Navigates to `/chat`** — removes modal overlay from App.tsx. Esc/body-overflow logic deleted. |
| State mgmt | **React Context** (Language, Auth) + localStorage persistence |
| Chat history | **ChatContext** manages messages array; persisted to localStorage |
| Deep-linking | **URL hash fragments** (e.g. `/about#who-we-are`) |
| Infrastructure | **Delete** metadata.json, assets/.aistudio/, server.ts, vite.config.ts, dist/, index.html |
| Tailwind | **v4 with `@tailwindcss/postcss`** (PostCSS plugin) |
| Lint | `tsc --noEmit` for type-check |

## Key Risks

1. **metadata.json deletion** — Contains `requestFramePermissions: ["camera", "microphone"]` used by AI Studio runtime. Deleting may break camera/mic auto-permission in AI Studio hosting. Standard browsers will prompt via `getUserMedia()` at point of use. **Risk accepted per user instruction.**

2. **Dead dependencies** — `motion` and `canvas-confetti` are in package.json but never imported in any source file. Can be safely removed.

3. **ProductModal** — Currently a modal in App.tsx. **Decision: keep as modal** rendered from Marketplace page via local state. No `/marketplace/[id]` route.

## API Routes (Next.js App Router format)

Each API endpoint becomes `app/api/<name>/route.ts` with `export async function POST/GET(request: Request)`.

### Migrate from `server.ts`:
1. **`app/api/health/route.ts`** — `GET` — health check (server.ts:27-33)
2. **`app/api/chat/route.ts`** — `POST` — Gemini chat (server.ts:36-130)
   - `GoogleGenAI` init with `process.env.GEMINI_API_KEY`
   - Same language map, system instruction, content building
3. **`app/api/disease-detect/route.ts`** — `POST` — Gemini vision (server.ts:133-252)
   - Same JSON schema with `responseSchema`

### New (from README spec):
4. **`app/api/auth/otp/route.ts`** — `POST` — request mock OTP (returns `2541`)
5. **`app/api/auth/verify/route.ts`** — `POST` — verify OTP (`2541` or `1234`), returns session token + farmer profile
6. **`app/api/mpesa/stkpush/route.ts`** — `POST` — simulate M-Pesa STK push (mock success)

### Express → Next.js adaptation:
- `req.body` → `const body = await request.json()`
- `res.json(data)` → `NextResponse.json(data)`
- `res.status(code).json(...)` → `NextResponse.json(data, { status: code })`
- Remove `express.json()` — Next.js parses JSON body automatically
- `GEMINI_API_KEY` → `process.env.GEMINI_API_KEY` (server-side only in API routes)

## State Management

### LanguageContext (`app/context/LanguageContext.tsx`)
- `currentLanguage: LanguageCode` — persisted to `localStorage['sautifarm_lang']`, default `'sw'`
- `setLanguage: (lang: LanguageCode) => void`
- Wraps app in `LanguageProvider`; consumers use `useLanguage()`
- `getTranslation` from existing `src/data/translations.ts` used internally by components

### AuthContext (`app/context/AuthContext.tsx`)
- `farmer: FarmerProfile | null` — persisted to `localStorage['sautifarm_user_profile']`
- `isAuthenticated: boolean`
- `login: (phone: string) => Promise<void>` — calls `/api/auth/otp` then `/api/auth/verify` (mock OTP `2541`)
- `logout: () => void`
- `openAuthModal: () => void` — sets `authModalOpen` state for DevPortal to trigger
- `authModalOpen: boolean` — controls auth modal visibility
- Default: `farmer = null` → auth modal shows on first interaction

### Note: No ChatContext needed for UI state
- Chat history is internal to `ChatAssistant` component (uses `useState` + `localStorage` like current code)
- The floating chat button in root layout calls `router.push('/chat')`
- No `chatOpen` context state — replaced by dedicated route

## Root Layout (`app/layout.tsx`)

Responsibilities:
1. Import `globals.css`
2. Set HTML `<html lang>` based on `currentLanguage`
3. Export `metadata` (title, description, themeColor, openGraph from `index.html` meta tags)
4. Export `viewport` config
5. Wrap children in `<Providers>` (LanguageProvider + AuthProvider)
6. Render `<Navbar />` — uses `useLanguage()` + `useAuth()` + `useRouter()` (via `usePathname` for active state)
7. Render `<Footer />` — uses same hooks
8. Render floating chat button (bottom-right) → `router.push('/chat')`
9. Render `<AuthModal />` when `!isAuthenticated` (triggered by context `authModalOpen` or first visit)

### Navbar active state
- Use `usePathname()` from `next/navigation` to highlight current route
- Map pathname to nav item active state (replaces `activeTab === item.id` checks)

### Scroll restoration
- Next.js App Router restores scroll automatically on back/forward
- For programmatic navigation, `router.push()` preserves scroll position by default
- Add `scroll-restoration.js` behavior: scroll to top on route change via `useEffect` in root layout with `usePathname` change detection

## Page Components

Each existing component in `src/components/` becomes a page in `app/`. The pattern:

1. Add `'use client'` directive at top (components use hooks, DOM APIs)
2. Replace prop-injected `currentLanguage` with `useLanguage()` hook
3. Replace `setActiveTab('route')` with `useRouter().push('/route')`
4. Replace `farmer` prop with `useAuth()` hook
5. Keep component logic identical otherwise

## Deep-Linking (initialSection → hash)

Components with `initialSection` prop: AboutUs, Services, Investors, InformationHub

**Implementation in page components:**
```tsx
'use client';
import { useEffect } from 'react';

export default function Page() {
  useEffect(() => {
    const hash = window.location.hash;
    if (hash) {
      const id = hash.substring(1);
      setTimeout(() => {
        document.getElementById(id)?.scrollIntoView({ behavior: 'smooth', block: 'start' });
      }, 100);
    }
  }, []);
  return <Component />;
}
```

**Footer deep-links:** Footer currently calls `setActiveTab('home')` for stories/crop calendar/video tutorials. Update to `router.push('/#stories-title')` etc. using section IDs that exist in HomeDashboard.

## PWA Configuration (`next.config.js`)

```js
const withPWA = require('next-pwa')({
  dest: 'public',
  disable: process.env.NODE_ENV === 'development',
  runtimeCaching: [
    {
      matcher: /^\/api\/.*/i,
      handler: 'NetworkFirst',
      options: {
        cacheName: 'api-cache',
        expiration: { maxEntries: 50, maxAgeSeconds: 60 },
        networkTimeoutSeconds: 10,
        cacheableResponse: { statuses: [0, 200] },
      },
    },
    {
      matcher: /^\/_next\/static\/.*$/,
      handler: 'CacheFirst',
      options: {
        cacheName: 'static-assets',
        expiration: { maxEntries: 100, maxAgeSeconds: 31536000 },

    },
  ],
});
```

- `next-pwa` handles SW registration automatically (no inline script in HTML needed)
- `public/manifest.json` and `public/icon.svg` remain as-is
- `public/sw.js` is replaced by next-pwa generated SW (delete old sw.js or let next-pwa overwrite)
